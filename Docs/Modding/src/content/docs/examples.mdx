## Larger connected mods

### Definitive Edition foundation

[DE128 source](https://github.com/dawc17/ProjectEclipse/tree/main/Mods/de128)
shows a downstream mod split into Lua modules with an explicit startup order.
Its Underworld battles use <a href={pageUrl('api/assets')}>audio asset handles</a>
for all 29 music IDs in the reviewed raid data. The mod ships PCM16 WAV files
and resolves them by their archive IDs, so battles do not depend on the base
game's substitute music. Battle mapping checks and a native Unity loader test
cover all 29 clips; audible playback in a fight has not yet been verified.
Its dojo chooser places a paintbrush button at the bottom-left of the story map.
It opens a padded game-style scroll with ten clickable dojo images, a visible
scrollbar and a highlight for the current selection. It uses a declarative
map-button quest and `map_button` story callback to select
an installed core location through the saved dojo API. Ten
archived choices have the required location data; two still need missing art or
params. See <a href={pageUrl('api/quests')}>Quests</a> and
<a href={pageUrl('api/locations-and-locales')}>Locations</a> for these APIs.
It makes new and saved pending forge orders eligible for instant completion and
disables the six supported service groups.
Its forge module also uses <a href={pageUrl('api/items-progression-forge')}>typed recipe and candidate APIs</a>
to split the archived Complex enchantments across three recipes and adjust the
Simple recipe's random power range. The added recipes borrow core Complex prices;
the package leaves DE-only Abilities recipes for later work.
It also defines Titan's Desolator with core art, native innate perks and a name
registered through <a href={pageUrl('api/localization-patches')}>Lua localization</a>.
The manifest requests `policy.timers`, `policy.services`, `content.register` and
`content.patch`, plus `combat.modify_outgoing_hit` and `combat.effects` for its
perk behaviors. Its story also needs `story.events`, `story.progression`,
`profile.read`, `state.read`, `state.write` and `ui.create`. Content is authored in
Lua without XML mod definitions. Its ChineseSwords module includes a recovered
animation binary, and its Sensei story ships its own portrait and battle-preview
sprites, passed to `avatar` and `preview` as sprite handles.

Saved forge deadlines are preserved until normal delivery settles the order;
`complete_pending = true` makes it eligible without paying to skip again.
Service flags suppress recognized quest groups and battle-pass source paths;
complete removal of every related UI surface is not established. See
<a href={pageUrl('api/timers-and-services')}>Timers and service settings</a> for the
public contract and the mod's README for its game checks. Its managed fixture
executes the real Lua and checks rollback, composition and rebuilding without
the mod; it does not replace a Unity playtest.

The integrated combat/offline-modes showcase also owns the forge timer. Disable
that showcase before trying DE128: competing timer policies fail explicitly.
Desolator has no purchase listing. DE128 now awards it through the Titan reward
path using typed grant-time configuration for equipment level and enchantments.
The package also installs a six-act Sensei story: battles on the existing map
pages, encounters, rewards, dialogue and unlock notifications. Two of its inputs
are synthesized where no source survives; the mod's production record explains
the evidence, and no full campaign playthrough has been recorded yet. The user confirmed only
that a manually added Desolator worked; that does not by itself validate the
reward callback's level/enchantment settlement, save persistence, combat behavior,
or runtime art rendering.

The source also includes a **pending Sensei story composition example** in
`scripts/content/sensei_story.lua`. It shows how owned fight-entry continuations,
saved dialogue cursors and battle-result subscriptions work together: install
victory handling before unlock notifications, and use the same qualified final
fight IDs for both. Portrait handles are supplied by the caller, so presentation
does not depend on a particular asset namespace. The combined managed fixture
checks six acts with controlled opponents and presentation hosts, including
loss/retry, saved dialogue and profile isolation. This code is not loaded by the
package entrypoint: verified opponent assets, perk availability, defeat dialogue
and a native campaign playtest remain outstanding. It is an integration example,
not a playable restored campaign.

The earlier Ascension prototype is disabled and is no longer part of the active
DE restoration path. Its generic public rule and encounter-plan APIs remain
documented because they are reusable modding features, but the DE package should
not be treated as currently restoring or demonstrating Ascension. Current DE work
has returned to XML-evidenced Definitive Edition content instead of substituting
prototype progression or economy behavior.

The active package now restores the archived **Master of Style** and **Relentless**
level-4 perk branch from `CharacterProgress.xml`, including paired upgrade choices
at levels 8, 11, 14 and 17 and the five XML rank values for each perk. Their Lua
behaviors follow the trigger definitions in `perks.xml`, not inferred aliases or
name similarity. One archived contradiction is preserved: the original English
Master of Style text says **Aggressive or higher**, while the trigger XML's style
conditions include the recovered native **Brutal** threshold. The implementation
follows the trigger XML and leaves the English text unchanged. This archive evidence
does not prove a particular DE64 or DE128 build identity.

The same XML comparison removes six obsolete direct move locks tied to the five
replaced gate perks. The affected moves are `DoubleJumpKick`, `BackFlipKick`,
`TwoFootJumpKick`, `ElbowStrike`, `ThrowSuplex`, and `ThrowSuplexProfile`; the two
suplex moves both use `PERK_SUPLEX`. `sf2.moves.remove_perk_lock` removes only the
exact direct perk lock shown absent in the archived move XML. It does not grant fake
legacy perks or remove the moves' remaining item, screen/profile, operator or
inherited-template restrictions.

The shop module exposes 25 existing items from the Guardian, Skanda, Wind Maker,
Time Shifter and Scriptwriter battle-pass collections at levels 15, 20, 25, 45 and
50 respectively. It uses <a href={pageUrl('api/shop')}>shop availability</a> with
`minimum_level`, retaining canonical prices, stats, upgrade rules and item IDs.
This demonstrates alternate shop access; it does not implement all archived set
abilities or equipment changes. Native icon/model-text loading and controlled
availability checks passed; purchases, equipment previews and save/reload still
need gameplay acceptance.

The equipment module also uses <a href={pageUrl('api/items-progression-forge')}>combat
subtype patches</a> to restore Naginata, HunterClaws, MagariYari and Kunai routing
on four existing items. Native condition/copy/rollback tests cover the mechanism.
ChineseSwords is now registered through typed Lua move definitions, including its
stance locks, four-hit super slash, profile title and shop preview. An isolated
native fight passed move selection, attack intervals and animation completion;
full hit-contact, AI and preview acceptance remains open.

The restored equipment modules add ten missing weapon definitions plus Dragon
Carapace, Old Legionnaire Armour, Samurai Armour, Gabled Helm, Dragon Helm,
Dragon Boomerangs, Dragon's Breath and Lightning Arc. They demonstrate localized
names, gem listings, act/level gates and default enchantments. Moon Fans uses
`initial_stats = {}` to preserve absent initial damage. Samurai Armour uses
`initial_stats = { head_defense = 914 }`, preserving the archive's head-only stats
instead of silently adding body defense. See the
<a href={pageUrl('api/equipment-shop-logging')}>equipment API</a> for snapshot rules.
Native definition and asset checks passed. These are item-definition restorations;
the shared-move module additionally demonstrates guarded
<a href={pageUrl('api/moves-and-tactics') + '#sf2movespatch'}>native move patches</a>
for interval duration, hit reaction, sound timing and selection conditions. Native
condition evaluation and patch restoration passed. Sphere1 and Sphere2 each demonstrate nine Lua-authored moves, with Minor and Medium
Charge of Darkness listings. Sphere2 uses three attack edges and distinct effects,
alignment and Stun restrictions. Archive comparisons and isolated native Magic-input selection, startup-to-flight
transition, charge consumption and child deletion pass. Numerical damage, visible
effects and shop-preview acceptance remain open.
Sphere3 adds five moves and Large Charge of Darkness, including enemy-centered
placement and the native `Physycal` reaction. Its isolated native cast, middle-phase
selection, charge and cleanup also pass. ComboSphere3 adds four moves and Blast of the Void, demonstrating a bounded attack
window and `HighLong` reaction. Its native casting, attack-phase selection, charge
and deletion checks pass. MindThrowNormal adds six moves and an innate Lua perk:
the cast sets an instance-owned flag, and the victim reaction or wall cleanup
clears it. A native `mod_expires` move event selects the caster's follow-up.
Its full graph and three perk trigger traces match the historical repository XML.
An isolated native fight passed contact in the normal idle stance, the owned
victim reaction, one flag expiry, follow-up selection and final attack interval.
The recovered projectile misses the native fixture's crouched fists idle pose;
other-stance contact and source-corpus reconciliation remain open. Remaining
preview differences, purchases, equipment use and save continuity need separate
acceptance work.

### Visual gameplay showcases

Enable one of these examples, choose **Apply & Restart**, enter the map and use
the bottom page dots to find its named zone. Each has its own battle; none requires
replaying a particular vanilla tournament fight. Disable auto-opening menu examples
if they cover the map. The menus use the original game's fonts and UI art, and the
fighters reuse native portraits and equipment.

| Example source | What you should see |
| --- | --- |
| [Pulse Guardian](https://github.com/dawc17/ProjectEclipse/tree/main/Mods/example.pulse-guardian) | A staff guardian's shield alternates every three combat seconds. A HUD meter and stopped/landed counters track the rule: incoming damage is zero during SHIELD UP and normal during SHIELD DOWN. |
| [Tactic Gallery](https://github.com/dawc17/ProjectEclipse/tree/main/Mods/example.tactic-gallery) | Four differently equipped opponents use patient kicks, footwork, alternating kicks and attack-window reactions. A live HUD reports the AI's requested action or native fallback. Win to reach the next brain. |
| [Arena Draft](https://github.com/dawc17/ProjectEclipse/tree/main/Mods/example.arena-draft) | A shuffled three-column opponent selector, Veteran toggle and timer slider determine the actual next fight. BACK cancels preparation; confirmed encounter plans persist through the normal save flow. |

Each folder includes a step-by-step acceptance checklist. The examples award no
items or currency, but save mode progress; use a test profile. The AI display
reports requests, not guaranteed hits. Drafting selects from authored fighters;
it does not generate new meshes or animations. Automated checks execute the exact
Lua scripts and mount the UI in an isolated Unity fixture; full-game combat and
physical-controller acceptance remain separate checks.

The [Grid UI Showcase](https://github.com/dawc17/ProjectEclipse/tree/main/Mods/example.grid-ui)
opens an original-style equipment selector when you enter a non-combat scene.
Enable it and restart, then enter the map to test three-column layout, scrolling,
selection, hidden/disabled cells and keyboard/controller navigation. It demonstrates
UI layout only; its buttons do not equip items.

Branching Trial and Seeded Trial reveal their battles when a map session begins.
After enabling either mod and restarting, use the bottom map-page dots to find
its named zone. With several example mods enabled, another example may initially
focus its own page. Each trial supplies a `zones/trial` localization for its map
footer; registering a battle alone does not reveal it.

Each trial has three named fighters with distinct original-game portraits and
equipment. Branching Trial uses **Gatekeeper** (kunai), **Bulwark** (steel batons)
and **Night Warden** (ninja sword). Its shortcut skips Bulwark. Seeded Trial uses
**Wayfarer** (unarmed), **Needlehand** (sai) and **Storm Ronin** (nunchaku); its
seeded choice either includes or skips Needlehand. These reuse native character
templates while registering separate mod-owned warriors. Existing saved route
positions and seeds survive the example update.

The [Charged Strike HUD](https://github.com/dawc17/ProjectEclipse/tree/main/Mods/example.charge-ui)
shows an anchored, localized HUD, live UI updates and a click that arms behavior for a fresh combat callback. Closing the HUD cancels the armed bonus.

## Try a change

1. Copy the complete example folder into the game's `Mods` directory if it is not already there.
2. Enable it through the title-screen **Mods** menu and choose **Apply & Restart**.
3. Follow the example's source README to reach its content in game.
4. Exit Eclipse, change one value, save, and launch again to compare.

For a separate mod, choose a new manifest ID and review references that explicitly include the original owner's ID. Do not install two copies with the same ID. Keep published IDs stable once players have saved progress with your mod.

## Shifting Guardian

`Mods/example.shifting-guardian` demonstrates the experimental
[`fighter:change_form`](../api/combat-callbacks/#fighterchange_form) workflow.
Enable it, Apply & Restart, select **Shifting Guardian** with the map's bottom
zone dots, and fight. After three seconds the staff opponent requests a baton
form. Its native-style HUD reports queued, applied or failed; queued is not proof
that the body changed. Check the weapon/name, continued combat, health percentage
and timer. Pause, early round ending and replay are useful lifecycle checks.

The Lua example and host fixtures are checked; full-game transformation acceptance
is pending. Active stolen magic and unresolved effect references can still fail
requests. This example has empty item rewards and does not replace an Act 1 fight.
